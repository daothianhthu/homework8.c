# HW08: 최소 비용 신장 트리(MST) 알고리즘 비교

## 1. 구현 개요

- 파일: `main2.c`
- 빌드: `gcc main2.c -o main2`
- 실행 환경: macOS/Linux
- 시간 측정: `clock_gettime(CLOCK_MONOTONIC, ...)`

정점 50개(0~49)를 갖는 가중치 무방향 단순 그래프를 사용한다. 간선 가중치는 1~100의 양의 정수이며, 자기 루프와 중복 간선은 허용하지 않는다.

희소 그래프는 100개, 밀집 그래프는 600개의 간선을 갖는다. 먼저 각 정점을 기존 정점에 연결하여 연결성을 확보하고, 나머지 간선을 무작위로 추가한다. 이후 단순 그래프 조건과 연결성을 검사한다.

각 그래프는 한 번 생성한 뒤 동일한 간선과 가중치를 유지하면서 인접 리스트와 인접 행렬로 각각 표현한다.

- Kruskal: 인접 리스트에서 간선을 수집하고 `qsort`로 정렬한 뒤 Union-Find로 사이클을 검사한다.
- Prim: 인접 행렬과 `key[]`, `parent[]`, `visited[]` 배열을 사용한다. 최소 key를 가진 미방문 정점을 선택하는 O(V²) 구현이다.
- 메모리: `sizeof`를 사용하여 그래프 표현과 알고리즘의 주요 보조 자료구조를 계산한다.
- 실행시간: 그래프 생성과 결과 출력을 제외하고 MST 계산을 2,000회 반복하여 평균 시간을 측정한다.

## 2. 실행 결과

다음은 한 번의 실행에서 얻은 결과이다. Case 1의 메모리는 Kruskal에서 선언한 임시 간선 배열의 실제 크기(600개)를 반영해야 한다.

| Case | 그래프               | 표현 및 알고리즘      | MST 간선 수 | MST 비용 | 메모리(Byte) | 실행시간(ms) |
| ---- | -------------------- | --------------------- | ----------: | -------: | -----------: | -----------: |
| 1    | Sparse (V=50, E=100) | 인접 리스트 + Kruskal |          49 |     1558 |       11,588 |     0.003627 |
| 2    | Dense (V=50, E=600)  | 인접 리스트 + Kruskal |          49 |      335 |       27,588 |     0.027490 |
| 3    | Sparse (V=50, E=100) | 인접 행렬 + Prim      |          49 |     1558 |       11,188 |     0.010995 |
| 4    | Dense (V=50, E=600)  | 인접 행렬 + Prim      |          49 |      335 |       11,188 |     0.010268 |

※ 메모리 값은 `sizeof(int)=4`, `sizeof(Node)=16`, `sizeof(Edge)=12`인 환경을 가정한 계산값이다. 실제 제출 시 프로그램에서 확인한 자료형 크기와 일치하는지 확인한다.

## 3. 성능 분석

### 3.1 희소 그래프와 밀집 그래프

Kruskal은 희소 그래프에서 0.003627 ms, 밀집 그래프에서 0.027490 ms를 기록했다. 간선 수가 100개에서 600개로 증가하면서 정렬해야 할 간선이 많아졌고, 실행시간도 증가했다.

Prim은 희소 그래프에서 0.010995 ms, 밀집 그래프에서 0.010268 ms를 기록했다. 두 그래프의 정점 수가 동일하므로 인접 행렬을 순회하는 작업량은 거의 같다. 측정값의 작은 차이는 실행 환경과 측정 오차의 영향을 받을 수 있다.

### 3.2 인접 리스트와 인접 행렬의 메모리

인접 리스트는 각 무방향 간선을 두 개의 노드로 저장하므로 간선 수가 증가할수록 메모리 사용량도 증가한다. Kruskal에서는 간선 배열과 Union-Find, MST 결과 배열도 필요하다.

인접 행렬은 50×50개의 정수 칸을 사용하므로 간선 수와 관계없이 행렬 자체의 크기가 일정하다. Prim의 보조 배열 역시 정점 수가 고정되어 있으므로 두 그래프에서 전체 계산 메모리가 동일하다.

이번 구현에서는 Kruskal의 임시 간선 배열이 600개로 고정되어 있어 희소 그래프에서도 해당 배열의 메모리를 전부 고려해야 한다. 따라서 그래프 표현만의 메모리와 알고리즘의 전체 메모리를 구분하여 해석해야 한다.

### 3.3 Kruskal과 Prim의 실행 특성

Kruskal은 간선을 가중치 오름차순으로 정렬하므로 일반적으로 O(E log E)의 시간 복잡도를 갖는다. Union-Find는 경로 압축을 사용하여 사이클 검사 비용을 줄인다.

Prim의 배열 기반 구현은 O(V²)의 시간 복잡도를 갖는다. 매 단계에서 최소 key 정점을 찾기 위해 정점 배열을 순회하므로 간선 수가 달라져도 정점 수가 같으면 주요 연산량이 크게 변하지 않는다.

### 3.4 실험 결과의 비교

- 희소 그래프에서는 Kruskal이 이번 실험에서 Prim보다 약 3.03배 빨랐다.
- 밀집 그래프에서는 Prim이 이번 실험에서 Kruskal보다 약 2.68배 빨랐다.
- 희소 그래프의 MST 비용은 두 알고리즘 모두 1558이었으며, 밀집 그래프에서는 모두 335였다.
- MST의 간선 수는 모든 경우에 49개로, 연결 그래프의 MST 조건인 V-1을 만족했다.

이 결과는 이번에 생성한 두 그래프와 해당 실행 환경에 대한 관측이다. 모든 그래프에서 동일한 성능 차이가 발생한다고 단정할 수는 없다.

## 4. 참고 및 한계

정점 수가 50개로 작아 실행시간이 매우 짧다. 따라서 측정값은 CPU, 컴파일러 최적화 옵션, 시스템 부하 등의 영향을 받을 수 있다. 반복 평균을 사용했지만 더 일반적인 결론을 내리려면 여러 그래프와 여러 번의 독립적인 실험이 필요하다.

메모리는 `sizeof` 기반으로 계산했으며, `malloc`의 관리 오버헤드와 프로그램 전체의 런타임 메모리는 포함하지 않는다.
